# Conciseness Guide

Patterns for reducing verbosity while preserving meaning. Apply per language rules from `language-rules.md`.

## Universal Patterns (All Languages)

### Remove Filler Phrases

| Verbose | Concise |
|---------|---------|
| `In order to` | `To` |
| `Due to the fact that` | `Because` / `Since` |
| `At this point in time` | `Now` / `Currently` |
| `For the purpose of` | `To` / `For` |
| `In the event that` | `If` |
| `With regard to` / `Regarding` | `About` / `On` |
| `It is important to note that` | *(remove)* |
| `Please note that` | *(remove)* |
| `It should be noted that` | *(remove)* |
| `As a matter of fact` | *(remove)* |
| `Basically` / `Essentially` / `Actually` | *(remove)* |
| `In terms of` | *(remove or rephrase)* |

### Replace Wordy Constructions

| Verbose | Concise |
|---------|---------|
| `make a decision` | `decide` |
| `perform an analysis` | `analyze` |
| `conduct an investigation` | `investigate` |
| `provide assistance` | `help` / `assist` |
| `give consideration to` | `consider` |
| `take action` | `act` |
| `reach a conclusion` | `conclude` |
| `effect a change` | `change` |
| `come to an agreement` | `agree` |
| `provide an explanation` | `explain` |

### Merge Redundant Sentences

**Before:**
> The system validates the input. The validation ensures data integrity. If validation fails, the system returns an error.

**After:**
> The system validates input for data integrity and returns an error on failure.

### Convert Passive to Active (When Natural)

| Passive | Active |
|---------|--------|
| `The file is created by the script` | `The script creates the file` |
| `An error will be returned` | `The function returns an error` |
| `Configuration is required` | `You must configure` / `Configuration is required` (keep if impersonal is clearer) |

**Exception:** Keep passive when the actor is unknown, irrelevant, or intentionally de-emphasized.

### Eliminate Redundant Modifiers

| Redundant | Clean |
|-----------|-------|
| `completely eliminate` | `eliminate` |
| `absolutely essential` | `essential` |
| `future plans` | `plans` |
| `past history` | `history` |
| `end result` | `result` |
| `free gift` | `gift` |
| `basic fundamentals` | `fundamentals` |
| `true facts` | `facts` |

## Application Rules

1. **Apply iteratively** — one pattern at a time, re-read after each pass
2. **Preserve nuance** — don't collapse `may` → nothing if uncertainty is real
3. **Keep technical precision** — `The function returns null` ≠ `Returns null` (subject matters for API docs)
4. **Respect document type** — tutorials need more connective tissue than reference pages
5. **Flag ambiguous cases** — `<!-- TODO: verify conciseness change preserves meaning -->`
